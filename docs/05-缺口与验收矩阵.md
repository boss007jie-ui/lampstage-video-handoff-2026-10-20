# 缺口与用户要求逐项核对

本表不是待开发功能的完成声明。本包完成实际源码和可审阅契约的交接；真实生成可还原验收仍有阻塞。

| 用户要求 | 本包交付 | 缺失/未验证 |
|---|---|---|
| video/types/backends/backend-runtime与依赖 | 原件和完整相对导入闭包；source-manifest逐文件SHA | 完整旧应用不是独立服务；Hypit实现未转交 |
| worker/配置/状态/schema | 原自有worker、profile配置脚本、类型枚举、schema与18迁移 | 不启动原worker，不提供业务数据库或Windows凭据模块 |

| 分阶段实际工作流 | 旧三模式、单次调用、W1/W2分别说明；脚本/分镜/TTS缺失明确 | 没有通用自动脚本→分镜→TTS全链；旧真视频生成依赖外部Hypit |
| 实际App/节点/完整导出 | 仅代码中只读workflowId明确保留，和缺口JSON | 真实webappId、nodeId、fieldName、required/default/range、完整可导入图均缺失；不拿测试值替代 |

## 接收方下一步先补的真值

1. 由实际应用所有者提供可转交的完整工作流JSON、AI应用调用映射与model/custom node清单；确认接收方账户能运行，或合法导入自有副本。App API调用示例只能提供可调字段，不能替代完整节点图。
2. 为每个业务阶段冻结实际AppID/映射版本/节点字段、类型/必填/默认/范围、上传返回值关系、音轨/图片顺序、模型版本与输出约束。仅有旧workflow ID或产品名不够。
3. 先实现宿主持久gate/原任务恢复/私有上传和收取端口，以本包无密钥测试验证语义；未核实模式保持关闭。原W1/W2不能直接注册为商家可用生成工具。
4. 费用和权限只用获授权的账户只读证据核对。日后如需真实付费样例，再由负责人另行明确预算和次数；本次没有代做。

以上缺失使“完整真实工作流可还原并生成”的部分尚不能验收；它们不会被一个模拟成功视频掩盖。本次不要求用户在聊天提供凭据，也不自动恢复功能开发或启动生产服务。
