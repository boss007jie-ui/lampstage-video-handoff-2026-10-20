# 实际流程、参数边界与可复用层

这份说明以 `source/` 当前代码为准，细致定位见 [workflow-audit](audits/workflow-audit.md)。不能把 W1/W2 的协议实现当成已接通的业务。

## 三条实际路径

| 路径 | 实际阶段 | 供应商接缝与交付状态 |
|---|---|---|
| 旧 `legacy_frames` | 用户提供需求/源视频/商品图 → 校验与冻结 → 切动作片/抽首尾帧 → 调图片服务生成参考帧 → 人工review → 按段生成 → 收取候选 → 合成 | `video/processor.ts`、`media.ts`、`image-reference.ts`；视频交给自有 `hypit-runner.ts` 调外部 Hypit；未交付其受限实现 |
| 旧 `direct_references` | 商品图+两张参考图 → 冻结/切片 → review → 分段生成/收取 → 直接合成 | `reference-inputs.ts`、`processor.ts`；没有六参考的accepted/末帧依赖门禁，仍调用Hypit |
| 旧 `six_references` | 每段1–6图与动作窗口 → 冻结/切片 → review → 逐段生成 → 候选hash/媒体检查/审阅 → 可选前段末帧接下一段 → 合成 | `six-reference-plan.ts`、`sixref-processor.ts`、`sixref-media.ts`；仍调用 Hypit |
| 新 `single_call` | 单个动作原片+1–6图+完整prompt → 免费校验 → 输入冻结/平台受理 → 单次生成 → 查询原build → 收取原始候选 | `video-calls/{contract,assets,service,engine,processor}.ts`；实际接API/Worker，但底层仍是 `sixRefRunner`；不自动分段、生成首尾帧或合成 |
| W1/W2新直连 | W1构造一次提交/查询；W2记录准备/审批/intent/lease/permit并收取候选 | `video/backends/`、`backend-runtime/`；生产dispatcher未接，`enabledModes=[]`，没有真实App节点映射；产物止于候选review，不是成片 |

没有在这些模块中实现通用“从一句需求自动写脚本→自动分镜→TTS配音”的完整规划器。旧流程的分镜是既有源视频时间线/显式语义窗口；单次调用的prompt由调用方提供。保留/补静音/拼回原音轨不等于配音生成。接收方应由已有 Harness 规划与 FFmpeg 安排这些步骤。

旧`legacy_frames`的参考帧生成也有实际自有实现：`image-reference.ts`经兼容入口`nano-banana.ts`调用OpenLux的`gemini-nano-banana-2.1`别名，源码端点为`/v1beta/models/gemini-nano-banana-2.1:generateContent`。`image-io.ts`顺序为第1张源时刻帧、第2张商品图，原生JSON inlineData传base64，返回图片由sharp裁成720×1280 PNG。请求构造与脱敏结构已随包；它是HTTP模型API，不是带App/nodeId的工作流。当前别名并不证明服务端精确模型构建版本，真实费用/账号权限本次未验证；direct/sixref/single_call不自动执行这一生成阶段。

## 输入与媒体限制：区分业务要求和供应商能力

- 旧源片：4–30秒、150 MiB、竖屏9:16，见 `video/types.ts` 与 `media.ts`；普通时间线请求4/5秒，有重叠裁切。
- 旧三参考：商品图+两张参考，固定三张；不是任意六图。
- 旧六参考：每段1–6图、请求4/5/6/8秒，语义窗口与时长偏移受15%约束；第1图为唯一start_state。`target-appearance-v2`是我方提示词配置版本，不是模型版本。
- 单次调用：`duration=4|5|6|8`，1–6图、prompt最多12000字符、role/label可选且最多80字符。原动作片须有真实音轨及audioCodec，最长30秒、画幅9:16、width≥144、height≤8192；不自动静音补轨。`max_credits`为平台积分授权，不是RH币。
- 旧合成目标：720×1280/30fps H.264，保留音轨时为AAC；旧生成SVML中有768P/9:16要求。这些均不能证明未知的新App有同样限制。
- W1新协议仅验证输入字符串和映射结构；每值最长1,000,000字符、必须正好匹配bindings键。它不知道某个App的数值范围、图片格式、时长、分辨率或音轨语义。

## 复用和替换

| 模块 | 可复用程度 | Harness应接管的部分 |
|---|---|---|
| W1 contracts/protocol/runninghub/registry | Node内置crypto+本地类型，可独立编译 | 真App映射、凭据注入、单次transport、持久gate、历史配置解析 |
| W2 collector | 独立可注入 | DNS及连接钉扎、禁止重定向下载、FFprobe、不可覆盖存储/readback |
| W2 binding/transitions/runner | 保留语义；依赖Lampstage Agent contracts/policy | 将记录、审批、租约/围栏映射到宿主，不能伪造actor |
| W2 preparer/prisma-runtime | Lampstage专用参考 | 接收方自己的任务与事务，不搬整套数据库 |
| single_call contract/engine | 可移植输入和单次决策 | IO端口；不可直接使用依赖Hypit的processor |
| 旧worker/processor/storage/API | 业务行为参考 | 已有队列、账号、资产、FFmpeg、费用系统 |

数据库的 VideoJob/VideoAsset/VideoPermit及Agent表结构保留在 `source/apps/web/prisma/`，仅供字段对照。并发上限3是代码策略，不是已核实的供应商账号配额。unknown会阻止该账户新提交，不能因旧租约失效就清除未知占用。
