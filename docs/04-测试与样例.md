# 可复现本地模拟、依赖与实际结果

## 最小安装层次

根`package.json/package-lock.json`是本次生成的精简测试依赖，锁文件v3、99个条目（包含root及可选平台包，不代表99个本机已安装包）。与原完整网站依赖清单分开；后者原样留在`source/apps/web/package*.json`作为追溯资料。

| 用途 | 精确版本/要求 |
|---|---|
| Node | 本次22.20.0，Windows x64；接收方需macOS相同或兼容版本 |
| npm | 本次11.19.1，只联网生成锁元数据，无第三方代码安装 |
| TS执行 | tsx4.22.4 |
| W2准备模块加载 | @prisma/client6.19.3；干净机器用prisma6.19.3生成client，不连接DB |
| 原参考输入模块加载 | sharp0.34.5；macOS需对应架构原生可选包 |
| 协议类型检查 | typescript5.9.3、@types/node20.19.42 |
| 媒体测试/本地样例 | 接收方已有FFmpeg/ffprobe，支持lavfi、libx264、mpeg4、AAC；本包不附二进制 |

W1四文件本身只有Node crypto和本地类型；若只复用W1，不必引入Prisma、sharp或原业务数据库。完整旧API/worker参考实现还用Next、AWS S3、bcryptjs等，详见`docs/audits/dependency-files.json`与原lock；这些不在精简测试依赖里，也不建议把旧应用整体装进Harness。

## 命令与真实结果

从本包根运行：

```sh
npm ci
npm run client:generate
npm run test:all-local
npm run test:samples
npm run typecheck:protocol
npm run example:local -- --run my-check
npm run example:local -- --run my-check
```

可将media单独运行`npm run test:media`，纯/内存组为`npm test`。两个组与all-local重叠，不可累计计数。测试脚本不用shell glob，适合macOS/Windows；offline-guard拒绝fetch/http/https/socket调用并剔除已知真实provider/数据库环境变量。它不是生产沙箱，只有列出的无DB测试被默认执行。

2026-10-20主线程实际执行：

- `node scripts/run-tests.mjs all`退出0：7文件，80项通过、失败0、跳过0，5431.2494ms。包括两份backend、state、preparation、collector及single_call contract/engine；TAP顶层77条，含3子项，总数80，不能另加。
- `tsc -p tsconfig.protocol.json`退出0：只证明W1四文件严格类型检查，不声称整个业务应用typecheck通过。
- 自造样例新记录`--run final-acceptance`退出0，submit/query/download=1/1/1。
- 同记录恢复退出0，submit/query/download=0/1/0，复用同一远端假ID和本地不可变receipt，未补发生成。
- 最终媒体实际probe：4秒、720×1280、H.264视频、AAC音轨。内容是几何颜色和合成正弦音，未调用AI服务。

本次已有依赖通过临时junction引用原`apps/web/node_modules`；未把安装目录转交。离线生成锁文件因缺registry缓存ENOTCACHED失败后，仅联网补锁文件元数据成功。没有执行干净`npm ci`或在macOS运行，没有新生成Prisma client、启动PG、桌面、旧Worker或真实供应商请求。相关实际日志位于`evidence/current/`；不能宣称新Mac安装已验证。

现有安装的直接版本与精简package一致；精简锁的完整传递依赖图没有在本次安装/验证。`test:samples`另校验10个合成响应案例及图片请求结构、取消unsupported、提交超时unknown三种场景；它是文档契约核对，不应与前述80项原测试重复计数。

## 最小完整模拟样例

代码：`examples/local-simulated-flow.ts`。包内`examples/generated/`保留本批第一次自造的输入、中间产物、journal、receipt和最终视频。目录及报告统一标为模拟，主要文件以SIMULATED命名；内部还有output.mp4、normalized-0.mp4、concat.txt和哈希命名对象JSON，均是本地模拟中间文件。运行默认命令会重放这份示例；使用`--run my-check`会在忽略的`examples/local-runs/my-check/`新建独立记录，同名再次运行是恢复，不删除已有样例。

| 阶段 | 输入/参数与依赖 | 实际中间/输出 |
|---|---|---|
| 需求/参考 | 自造144×256蓝色4秒动作片+440Hz音轨、橙色PPM图；无用户素材 | SIMULATED-motion.mp4、SIMULATED-reference.ppm、输入hash |
| 提交阶段 | 假App/4个假节点、duration4、假上传引用；只注入fake transport | 先保存submitting journal，再保存假taskId |
| 恢复查询 | 原backendId/taskId，1次本地fake outputs响应 | 绿色144×256/4秒候选（FFmpeg在本机预先合成） |
| 收取 | 注入fake DNS/字节流，真实probe、create-only对象和完整readback | sha/size/media/identityDigest receipt、下一阶段输入MP4 |
| 后期 | 候选+原动作片音轨，调用原assembleVideo | SIMULATED-final.mp4，4秒720×1280 H.264/AAC |

**这是接口与恢复语义的可复现模拟，不是最小真实生成工作流。** 假节点/上传引用与本地文件均不能发给真实服务商。串行文件journal示范不提供生产并发事务、审批、跨进程锁或真实账号校验；这些由接收方已有组件实现。原测试中的Set/MemoryStore也不能当生产gate。
